# 前端自动化测试指引（KIMI WEB BRIDGE）

> 本文档面向自动化测试工具与 QA，覆盖 StoryOS 前端全部 11 个视图。每个视图包含：元素定位表（data-testid）、操作步骤、断言点、功能效果评估（预期效果 / 合格标准 / 失效模式 / 依赖条件）。

---

## 环境准备

### 启动

```bash
# 后端（API 服务）
cd story-engine/backend
# 确保 .env 配置了 LLM API（或使用 MOCK 模式）
python -m uvicorn main:app --reload --port 8000

# 前端（Vite dev server）
cd story-engine/frontend
npm run dev    # 默认 http://localhost:5173
```

### 测试浏览器

- Chromium 系（Chrome / Edge），支持 `data-testid` 属性选择器
- 建议 Playwright / Cypress / Selenium 均可

### 选择器策略

**统一使用 `data-testid` 属性定位**，不依赖 class（class 随样式重构变化）：

```javascript
// Playwright 示例
page.click('[data-testid="nav-projects"]')
page.fill('[data-testid="project-name-input"]', 'test-project')
```

### MOCK vs 真实 LLM

| 模式 | 特征 | 适用场景 |
|------|------|---------|
| MOCK 剧本 | 顶栏显示 `MOCK 剧本` 徽章；生成返回固定文本；无需 API key | 流程测试、UI 回归 |
| 真实 LLM | 顶栏显示模型名；生成 20-120s；文本质量有随机性 | 功能评估、质量验收 |

> **功能评估合格标准仅在真实 LLM 下有意义**。MOCK 模式只验证 UI 流程不崩。

## 1. 项目页

### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `project-card-{name}` | 项目卡片 | 每个 `name` 对应一张卡 |
| `project-continue` | 继续按钮 | 切换到该项目 |
| `project-export` | 导出按钮 | 下载 zip |
| `import-zip` | 导入 zip 按钮 | 顶部操作 |
| `new-project` | 开新项目按钮 | 跳转抽卡页 |
| `new-project-empty` | 空态开新项目按钮 | 无项目时显示 |

### 操作步骤

1. 点击 `nav-projects` → 进入项目列表页
2. 断言：页面加载后出现项目卡片（或有空态提示）
3. 若有项目卡片：点击 `project-continue` → 页面刷新（`window.location.reload`），跳到写作台
4. 若有项目卡片：点击 `project-export` → 浏览器触发 zip 下载
5. 点击 `import-zip` → 系统文件选择器弹出
6. 点击 `new-project` → 跳转到抽卡页（gacha 视图）

### 断言点

- 项目卡片显示：名称、题材（中文 title）、文化、章数 · tick、最后打开时间
- 当前项目卡片有 `.current` 类 + 「当前」徽标
- 非当前项目的「继续」按钮可点击；当前项目显示「进行中」（disabled）

### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 多项目列表展示、一键切换、zip 导入导出 |
| 合格标准 | 卡片数 ≥1（已有项目时）；导出 zip 可被 `import-zip` 导回；切换后 SPA 重拉 config+project |
| 失效模式 | 后端未连接 → toast 报错；zip 格式不符 → 400；项目重名 → 409 toast 提示改名 |
| 依赖条件 | 后端 `/api/projects` 可用；导入需有效 zip（含 project.json） |

## 2. 开局向导七段式

### 总览

开局向导采用五段式面包屑（题材→骨架→世界观向导→人物原型→冲突检测→宏观规划），由 `stage` 状态机控制。

### 2.1 段 1：题材选择

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `genre-card` | 题材卡片 | 每张可选 |
| `synth-genre` | AI 自由发挥按钮 | 调用 LLM 合成 |
| `gacha-next-skeleton` | 下一步：选择骨架 | 选中题材后可点击 |

#### 操作步骤

1. 从项目页点击 `new-project` → 进入题材选择段
2. 断言：题材卡片网格出现（≥1 张卡片）
3. 点击任一 `genre-card` → 卡片高亮（`.selected`）
4. 点击 `gacha-next-skeleton` → 进入段 2（骨架选择）
5. 或点击 `synth-genre` → 显示 loading（20-60s）→ 显示合成结果

#### 断言点

- 题材列表加载完成后：卡片数 ≥1
- 选中题材后：`gacha-next-skeleton` 按钮 enabled
- synth 模式 loading 期间显示已等待秒数

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 用户从题材库选择或 AI 合成一个题材 |
| 合格标准 | 题材卡片数 ≥5；每张卡含 title/desc/castSummary；synth 模式在 60s 内返回 |
| 失效模式 | 题材库为空 → 「暂无可用题材」+ 重载按钮；synth 超时 → toast 报错 |
| 依赖条件 | `/api/gacha/draw` (library/synth)；synth 需真实 LLM |

### 2.2 段 2：骨架选择

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `skeleton-card` | 骨架预设卡片 | 10 个预设 + 随机 + 空白 |
| `skeleton-back` | 返回题材 | 回到段 1 |
| `skeleton-next` | 进入向导 | 进入段 3 |

#### 操作步骤

1. 点击任一 `skeleton-card` → 卡片高亮
2. 点击 `skeleton-next` → 进入段 3（世界观向导）

#### 断言点

- 骨架卡片数 ≥10（含随机 + 空白）
- 选中后 `skeleton-next` enabled

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 选择世界观骨架作为基底（10 预设 / 随机 / 空白自定义） |
| 合格标准 | 预设卡 ≥10；每张含 name/vibe/highlights |
| 失效模式 | schema 加载失败 → toast 报错 |
| 依赖条件 | `/api/worldview/schema` |

### 2.3 段 3：世界观向导（十层）

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `wizard-param-chip` | 参数选项 chip | 每层参数的可选值 |
| `wizard-prev-layer` | 上一层导航 | 左栏或底部 |
| `wizard-next-layer` | 下一层导航 | 底部 |
| `wizard-go-cast` | 下一步：人物原型 | 最后一层底部 |

#### 操作步骤

1. 进入向导后，左栏显示层进度轨（L0-L9 + LANG1-LANG5）
2. 右栏显示当前层参数卡片
3. 点击 `wizard-param-chip` 选中参数值 → chip 高亮
4. 点击 `wizard-next-layer` 前进 / `wizard-prev-layer` 后退
5. 到最后一层后点击 `wizard-go-cast` → 进入段 4

#### 断言点

- 选中参数后 chip 有 `.selected` 类
- 跨层违例时：违例 chip 红色标注 + 底部 violation 列表
- 校验通过时：显示「✓ 暂无跨层违例」
- 进度轨显示层状态（done/violation/current/todo/pending）

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 逐层配置世界观参数（L0-L9 + LANG1-LANG5），实时跨层校验 |
| 合格标准 | 可配置层 ≥10 层；校验 API 在 300ms 内返回违例信息 |
| 失效模式 | 校验超时 → toast 报错（不阻塞）；占位层显示「即将上线」 |
| 依赖条件 | `/api/worldview/evaluate`（每次选择后 300ms 防抖调用） |

### 2.4 段 4：人物原型

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `cast-card-{idx}` | 角色卡 | 0=主角，1+=配角 |
| `cast-auto-derive` | AI 自动分配按钮 | 从世界观推导 |
| `cast-add` | 添加配角按钮 | 最多 9 张卡 |
| `cast-back` | 返回向导 | 回到段 3 |
| `cast-next-crosscheck` | 下一步：冲突检测 | 进入段 4.5 |

#### 操作步骤

1. 进入人物段后默认 1 张主角卡
2. 点击 `cast-auto-derive` → AI 推导角色（需 LLM）
3. 在 `cast-card-0` 的输入框填入主角名（必填）
4. 点击 `cast-add` → 新增配角卡（最多 9 张）
5. 点击 `cast-next-crosscheck` → 进入段 4.5

#### 断言点

- 主角卡（idx=0）标有「主角」徽标
- AI 推导成功后：卡数 ≥1，每张含 name + role + persona
- 主角名为空时仍可进入下一段（但 confirm 时会提示）

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 配置人物原型阵容（主角必填 + 最多 8 配角），支持 AI 推导 |
| 合格标准 | AI 推导返回 ≥1 角色；每角色含 persona 键值；配角上限 8 |
| 失效模式 | 推导失败 → toast 报错（不阻塞，可手动填）；推导超时 → 不崩 |
| 依赖条件 | `/api/worldview/derive_cast`；需真实 LLM |

### 2.5 段 4.5：跨层冲突检测

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `crosscheck-back` | 返回人物 | 回到段 4 |
| `crosscheck-back-wizard` | 回③修改设定 | 回到段 3 |
| `crosscheck-accept` | 接受继续 | 进入段 5 |

#### 操作步骤

1. 自动扫描跨层冲突（5 类：题材×力量体系 / 人物×社会 / 力量多源 / 基调×节奏 / 语言×密度）
2. 断言：显示 loading → 结果（✅ 无冲突 / ⚠️ 冲突列表）
3. 点击 `crosscheck-accept` → 进入段 5（宏观规划）

#### 断言点

- 无冲突时：显示绿色 ✅ + 「所有层次对齐」
- 有冲突时：按 severity（HIGH/MEDIUM/LOW）列出警告卡
- 冲突被接受后标记传递给宏观规划（`conflictAccepted = true`）

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 自动检测跨层冲突，用户接受后约束注入宏观规划 |
| 合格标准 | 检测覆盖 ≥5 类冲突；每条含 type/severity/title/description/suggestion |
| 失效模式 | 检测失败 → toast 报错（不阻塞，可直接进入下一段） |
| 依赖条件 | `/api/worldview/cross_check` |

### 2.6 段 5：宏观规划

#### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `macro-template-card` | 幕结构模板卡 | 选择 15 拍/三幕等 |
| `macro-total-episodes` | 总集数约定输入框 | 1-500，默认题材回传值（12） |
| `macro-generate` | AI 生成宏观计划 | 调用 LLM |
| `macro-regenerate` | 全局重摇 | 重新生成 |
| `macro-skip` | 跳过宏观计划 | 直接开工 |
| `macro-back` | 返回冲突检测 | 回到段 4.5 |
| `confirm-start` | 确认开工（顶部） | 弹出确认对话框 |
| `project-name-input` | 项目名输入框 | 确认对话框内 |
| `confirm-cancel` | 取消开工 | 对话框内 |
| `confirm-ok` | 确认开工（对话框内） | 真正创建项目 |

#### 操作步骤

1. 选择模板（`macro-template-card`）→ 默认 `save_the_cat_15`
2. 在 `macro-total-episodes` 填总集数（默认 12，区间 1-500）→ 幕拍点按集数定位
3. 点击 `macro-generate` → 生成宏观计划（六大组件，分集条数 = 约定集数）
4. 断言：生成后展示 MacroDashboard（蓝图/节奏曲线/分集/弧光/伏笔/幕结构）
5. 可点击 `macro-regenerate` 重摇 / 单组件重摇
6. 点击 `confirm-start` → 弹出确认对话框
7. 在 `project-name-input` 填入项目名 → 点击 `confirm-ok` → 创建项目并跳转写作台
8. 或点击 `macro-skip` → 跳过宏观计划直接确认（集数约定仍落盘 project.json）

#### 断言点

- 模板列表加载后：卡片数 ≥1
- 生成完成后：MacroDashboard 显示 ≥3 个组件区域
- 确认对话框：项目名校验（中文/字母/数字/-/_，≤40 字符）
- 项目重名 → 409 toast
- 成功后 `window.location.reload()` 跳到写作台

#### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | AI 生成完整宏观计划（蓝图/节奏/分集/弧光/伏笔/幕结构六大组件） |
| 合格标准 | blueprint 含 logline + thematic_argument + central_conflict；episodes ≥3；beats ≥4；arcs ≥1 |
| 失效模式 | LLM 超时 → toast 报错（不阻塞，可跳过）；生成空 plan → 组件区域不显示 |
| 依赖条件 | `/api/macro/templates` + `/api/macro/plan`；需真实 LLM |

## 3. 写作台

### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|
| `write-empty-plan` | 空态「看第 1 章方案」 | 零章冷启动 |
| `write-empty-gacha` | 空态「抽卡开局」 | 零章冷启动 |
| `chapter-item-{no}` | 章节列表项 | 左栏 binder |
| `paragraph-{i}` | 段落元素 | 手稿区，i=0 基序号 |
| `gen-plan` | 生成下一章 | 看方案 |
| `gen-confirm` | 批准生成 | 确认生成 |
| `gen-discard` | 作废 | 废弃方案 |
| `gen-goto-review` | 进入审读 | 跳到手稿区 |
| `gen-archive` | 归档本章 | 归档收口 |
| `gen-rollback` | 回滚本章 | 触发回滚确认 |
| `gen-rollback-confirm` | 确认回滚 | 内联确认 |
| `gen-rollback-cancel` | 取消回滚 | 内联确认 |
| `fab-edit` | 改字 fab | 段落操作 |
| `fab-wrong` | 这不对 fab | 段落操作 |
| `fab-rewrite` | 重写这段 fab | 段落操作 |
| `fab-note` | 记一笔 fab | 段落操作 |

### 操作步骤

#### 冷启动（零章）
1. 点击 `write-empty-plan` → 触发 `startPlan()`
2. 断言：GenConsole 显示方案预览（轨道调度 + 节拍 + 钩子）

#### 生成流程（plan → confirm → review）
1. 点击 `gen-plan` → GenConsole 显示决策卡预览
2. 断言：预览含轨道行（advance/seed/mid_touch/dormant）+ 节拍 + 钩子
3. 点击 `gen-confirm` → 进入 generating 态（全局锁 + 进度条）
4. 断言：步骤骨架显示（决策卡 ✓ → 初稿生成 → 硬约束验证 → …）
5. 生成完成后自动进入 review → 显示步骤回放
6. 断言：回放含 ≥6 步骤（决策卡/初稿/硬约束/修正/事件库/快照）

#### 审读与归档
1. review 态下点击 `gen-goto-review` → 滚到手稿区
2. 断言：手稿段落数 ≥3；每段可点击
3. 点击 `gen-archive` → 归档本章 → 回到 idle 态
4. 或点击 `gen-rollback` → 内联确认条 → 点击 `gen-rollback-confirm`

#### 段落操作
1. 点击任一段落 `paragraph-{i}` → 展开 fab 工具条
2. 点击 `fab-edit` → 行内编辑器（textarea）→ Ctrl+Enter 确定
3. 点击 `fab-rewrite` → 方向输入 + 预设 chip → 生成重写 → 采用/换方向/放弃
4. 点击 `fab-note` → 类型 chip（伏笔/提醒/设定）+ 文本 → 记账
5. 点击 `fab-wrong` → 四类诊断 → 记入判断 / 跳转重写

#### 断言点

- 流程条四步（看方案/等生成/审读/提交归档）状态标记随 flow 变化
- 生成中全局锁：fab 按钮不可用，显示「正在生成中…」
- 生成失败：保留方案预览（不消失），显示红色错误横幅，可重试
- 段落已读标记（sessionStorage 记忆，切章按 timestamp 隔离）
- 右栏 rail：介入流 + 训练信号 + 本章关联 CFPG

### 功能效果评估

| 维度 | 内容 |
|------|------|
| 预期效果 | 两阶段生成（看方案→批准→生成→审读→归档/回滚）+ 段落四操作 |
| 合格标准 | 生成手稿 ≥3 段 · ≥800 字；beats ≥4；硬约束 0 违规（或已修正）；事件 ≥3 个；重写返回 diff（原文 vs 重写） |
| 失效模式 | LLM 超时 → 错误 toast + 保留方案可重试；MOCK → 固定文本回退；重写空 → 兜底提示用「改字」 |
| 依赖条件 | `/api/project/plan` + `/api/project/generate` + `/api/paragraph/rewrite` + `/api/intervene` |

## 4. 规划图

### 元素定位表

| data-testid | 元素 | 说明 |
|-------------|------|------|

1. **项目页**：验证卡片列表 / 导入导出
2. **设置页**：验证 LLM 卡片 / 连接测试 / 主题切换
3. **写作台**：冷启动 → 看方案 → 批准生成 → 审读 → 归档（MOCK 文本）
4. **决策卡**：验证字段展示
5. **人物/世界观/时间线/伏笔**：验证数据渲染不崩

### 功能评估（真实 LLM，~30 min）

1. **开局向导七段式**：题材→骨架→向导→人物→冲突→宏观→确认开工
   - 断言：宏观计划含 ≥3 组件 / beats ≥4 / episodes ≥3
2. **写作台全流程**：plan → confirm → review → 归档
   - 断言：手稿 ≥3 段 · ≥800 字 / 硬约束 0 违规 / 事件 ≥3 个
3. **段落操作**：改字 / 重写 / 记一笔 / 诊断
   - 断言：重写返回 diff / 改字回写生效 / rail 介入流更新
4. **规划图**：验证六大组件渲染
5. **人物介入**：角色介入弹窗提交 → 下章决策卡生效

2. 主题切换：日间→夜读→日间，断言无样式残留
3. 字号增减：+/- 各一次，断言 toast 出现
4. 项目导出→导入：zip 往返一致性
